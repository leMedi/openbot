OpenBot: focused local assistant

A small TanStack web app with a SQLite/Drizzle durable turn queue, one OpenAI-compatible model configuration, local agent/group conversations, memory, shell/read tools, and MCP plugin flows.

Grok Bot: desktop + host platform

An Electron renderer backed by a host/coordinator/gateway and isolated box runtime, with browser/computer tools, cloud agents, automations, memory synthesis, attachment services, telemetry, auth/secrets, and object-store synchronization.

Architecture at a glance

These are the product boundaries that explain many “Different” and “Missing” statuses. Generated protocol bindings are infrastructure, not counted as separate user-facing features.

OpenBot

Browser / TanStack UI→ route + server handlers→ SQLite / Drizzle→ turn runner→ OpenAI-compatible model

Tools, memory, MCP, and managed files are local package extensions around one application process/runtime.

VS

Grok Bot 0.18

Electron renderer→ Electron main→ host / gateway→ coordinator + box daemon→ extensions + cloud services

The host composes per-turn tools and mediates isolation, auth, cloud agents, automation wakes, telemetry, and synchronized state.

Gap analysis

A practical parity sequence if the goal is to move OpenBot toward Grok's broader product surface.

Parity is not the same as product scope.

Many Missing rows are intentional boundaries of OpenBot's one-user/local MVP rather than defects: the authoritative context documents no tenant/ACL model and explicitly defers bounded group selection and user-uploaded attachments. The priorities below are therefore conditional parity work, not a claim that every Grok subsystem belongs in OpenBot.

P0

Execution surface and trust boundaries

Add an explicit web search/fetch layer, browser/computer automation, and a real isolated workspace/sandbox before expanding autonomous capabilities. Pair this with authentication, secret storage, permission/review gates, and path/network policy.

P0

Long-running and remote work

Introduce a first-class subagent/task model and cloud-agent lifecycle rather than stretching the local turn queue. Persist status, transcript, artifacts, follow-ups, cancellation, and reconnect semantics.

P1

Automation and memory intelligence

Add scheduled and event-triggered routines, connector relays, and user-visible run history. Add evidence-backed memory synthesis/verification while preserving OpenBot's existing scoped memory tools.

P1

Media and attachment services

Complete the attachment UX, then add safe link previews, media processing/image generation, image-to-agent channels, and cloud artifact transfer with size/path checks.

P2

Product-shell parity

Expose provider/model selection, real voice capture/transcription, nested/persisted threads, desktop lifecycle affordances, richer diagnostics, telemetry controls, and synchronized backups only where the product needs them.
